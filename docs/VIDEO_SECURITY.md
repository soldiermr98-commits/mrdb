# امنیت ویدیو — نقشهٔ راه لایه‌بندی‌شده

> 📌 **حقیقت تلخ اما لازم:** URL ویدیو همیشه در DevTools مرورگر قابل دیدن است — این یک حقیقت اساسی وب است و هیچ کد جاوااسکریپتی نمی‌تواند آن را تغییر دهد. مرورگر باید URL را بداند تا ویدیو را دانلود کند. حتی اگه URL را در HTML نگذاریم، در تب **Network** همیشه قابل دیدن است.
>
> هدف ما **نه** «پنهان‌کردن URL» (غیرممکن) بلکه **«بی‌فایده‌کردن URL هنگام اشتراک‌گذاری»** است.

## وضعیت فعلی (v1.5.2)

| لایه | پیاده‌سازی‌شده | تأثیر |
|---|---|---|
| بلیط موقت ۱۵دقیقه‌ای | ✅ | بدون بلیط، URL از سرور نمی‌آید |
| واترمارک اختصاصی کاربر | ✅ | شناسه کاربر روی تصویر |
| Allowlist هاست ویدیو | ✅ | فقط هاست‌های مجاز قابل پخش |
| Rate limit روی بلیط | ✅ | ۳۱ درخواست در ساعت از یک IP |
| controlsList + disablePictureInPicture | ✅ | دکمه‌های دانلود/ریموت پخش مخفی |
| `draggable="false"` | ✅ | drag-and-drop غیرفعال |
| `preload="metadata"` | ✅ | فقط metadata بارگذاری می‌شود (نه کل فایل) |

**مشکل فعلی:** URL ای که از سرور می‌آید، **دائمی** است — هرکسی آن را داشته باشد می‌تواند ویدیو را دانلود کند، حتی بدون لاگین.

## لایهٔ ۱ — Hotlink Protection (الان پیاده‌سازی شد ✅)

**هاست:** cPanel 138 + Apache 2.4.67 + BitNinja WAF (60GB package)

**فایل‌ها:**
- `docs/DLL_HOST_HTACCESS.sample` — فایل `.htaccess` آماده (Apache 2.4 syntax)
- `docs/DLL_HOST_INSTALL.md` — راهنمای گام‌به‌گام نصب و تست

**تأثیر:**
- ✅ URL از `app.mrdastbaaf.com` کار می‌کند
- ❌ URL کپی‌شده در آدرس‌بار مرورگر → 403 Forbidden
- ❌ Hotlink از سایت/تلگرام/اینستاگرام → 403
- ❌ wget/curl بدون Referer → 403
- ✅ موتورهای جستجوی مجاز (Google/Bing/Yandex) → دسترسی دارند
- ✅ کاربران بدون Referer (privacy browsers) → دسترسی دارند (fail-open)

**محدودیت:** یک هکر می‌تواند Referer را جعل کند (با curl `--referer` یا افزونه‌های مرورگر). این لایه ۹۰٪ اشتراک‌گذاری کژوال را متوقف می‌کند، نه ۱۰۰٪.

**نصب:** فایل `docs/DLL_HOST_HTACCESS.sample` را به‌عنوان `.htaccess` در ریشهٔ `dll.mrdastbaaf.com` (جایی که پوشهٔ `FA/` هست) قرار دهید. راهنمای کامل در `docs/DLL_HOST_INSTALL.md`.

**تست زندهٔ قبل از اعمال (تأیید مشکل):**
```
بدون Referer:            HTTP 200 ← ویدیو سرو می‌شود (مشکل!)
با Referer telegram:      HTTP 200 ← ویدیو سرو می‌شود (مشکل!)
```
هدف: بعد از اعمال، باید تبدیل شوند به:
```
بدون Referer:             HTTP 200 (اجازه — برای کاربران قانونی بدون Referer)
با Referer app:           HTTP 200 (اجازه — پخش در اپ)
با Referer telegram:      HTTP 403 (رد — hotlink متوقف شد)
با Referer evil-site:    HTTP 403 (رد)
```

**توجه دربارهٔ BitNinja WAF:** هاست شما از BitNinja-WafPro به‌عنوان reverse proxy جلوی Apache استفاده می‌کند (header `server: BitNinja-WafPro`, `via: 1.1 Caddy`). این به این معناست که BitNinja درخواست را اول می‌بیند، ولی `.htaccess` همچنان توسط Apache پردازش می‌شود. اگه با وجود `.htaccess` درست، hotlink همچنان کار کرد، باید به پشتیبانی هاست تیکت بزنید و بپرسید «آیا BitNinja قبل از Apache Referer را strip می‌کند؟».

## لایهٔ ۲ — PHP Streaming Proxy (برای آینده)

**هدف:** URL واقعی هرگز به کاربر نمی‌رسد. `<video src="/wp-json/.../stream?token=...">` — اگه کسی در DevTools هم ببیند، URL کپسوله و کوتاه‌عمر است.

**طرح:**
```
GET /wp-json/mrdastbaaf/v1/lessons/{id}/stream?token=xxx
   ↓
   بررسی توکن: user_id + lesson_id + expiry (60 ثانیه)
   ↓
   PHP از dll.mrdastbaaf.com فایل را می‌خواند و byte-by-byte به کلاینت stream می‌کند
   ↓
   کلاینت فقط /wp-json/.../stream را می‌بیند، هرگز dll.mrdastbaaf.com
```

**مزایا:**
- URL واقعی هرگز لو نمی‌رود
- توکن کوتاه‌عمر (۶۰ ثانیه) — حتی اگه کسی آن را کپی کند، بعد از ۶۰ ثانیه بی‌اثر است
- بدون نیاز به CDN با قابلیت signed URL

**معایب:**
- بار سرور بالا (PHP باید هر بایت را پروکسی کند)
- پهنای باند double مصرف می‌شود (CDN → server → client)
- روی هاست اشتراکی، برای ویدیوهای طولانی ممکن است timeout بزند
- کیفیت تجربه کاربر ممکن است افت کند (به‌خصوص برای seek)

**پیشنهاد:** این لایه را فقط برای ویدیوهای بسیار حساس پیاده‌سازی کنید (مثلاً ویدیوهای اختصاصی استاد برجسته). برای بقیه، لایه ۱ + لایه ۳ کافی است.

## لایهٔ ۳ — HLS با URL امضاشده (راه‌حل ایده‌آل)

**هدف:** MP4 → HLS chunks. هر chunk امضاشده با TTL کوتاه. حتی اگه ۱۰۰ chunk هم بگیری، ویدیو کامل نیست و tokens منقضی شده‌اند.

**طرح:**
```
ویدیو اصلی: lesson-01.mp4 (۲ گیگابایت)
   ↓ ffmpeg
lesson-01.m3u8 + 1000 × segment-001.ts ... segment-1000.ts

هر segment با URL امضاشده:
https://dll.mrdastbaaf.com/.../segment-001.ts?token=...&expires=300

توکن: HMAC-SHA256(user_id + lesson_id + segment_id + expires)
TTL: 5 دقیقه
```

**مزایا:**
- نزدیک‌ترین به DRM واقعی روی وب
- Seek سریع (فقط chunk مربوطه دانلود می‌شود)
- ذخیرهٔ پهنای باند (کاربر فقط چیزهایی که می‌بیند را می‌گیرد)
- کیفیت‌سوییچ خودکار (HLS adaptive bitrate)

**معایب:**
- نیاز به CDN با قابلیت signed URL (مثل ArvanCloud، Cloudflare، Bunny CDN)
- یا نیاز به PHP middleware برای امضای هر درخواست (کمی پیچیده‌تر از لایه ۲)
- تبدیل MP4 → HLS با ffmpeg (اسکریپت آماده در `scripts/encode-qualities.sh` — فقط باید خروجی را به HLS تغییر دهیم)

**آماده‌سازی آینده:** کد پلاگین فیلتر `mrdastbaaf_stream_video_url` را دارد که برای این منظور طراحی شده — فقط باید یک افزونهٔ ثالث بنویسد که URL را به HLS امضاشده تبدیل کند. این کار بدون تغییر کد اصلی پلاگین ممکن است.

## کارهای عملیاتی فعلی

۱. **همین حالا:** فایل `docs/DLL_HOST_HTACCESS.sample` را به‌عنوان `.htaccess` در ریشهٔ `dll.mrdastbaaf.com` قرار دهید.
۲. **تست:** یک URL ویدیو را کپی کنید و در آدرس‌بار مرورگر جدید بچسبانید → باید 403 Forbidden بگیرید.
۳. **تست:** در اپ مستر دستباف، یک ویدیو را پخش کنید → باید بدون مشکل کار کند.
۴. **اگه نیاز به لایه ۲ داشتید:** در چت بعدی بگویید تا PHP streaming endpoint را اضافه کنیم.
