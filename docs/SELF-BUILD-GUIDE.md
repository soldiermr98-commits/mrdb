# راهنمای بیلد شخصی (Self-Build Guide)

این راهنما برای روزهایی است که خودتان می‌خواهید تغییرات جزئی بدهید و نسخهٔ جدید بسازید —
بدون نیاز به ابزار خارجی. **کل سورس در همین مخزن است**؛ ZIPهای مرکز دانلود فقط «خروجی بیلد» هستند.

---

## ۱) پیش‌نیازها (یک‌بار برای همیشه)

| ابزار | نسخه | دریافت |
|---|---|---|
| Node.js | ۲۰ یا بالاتر | https://nodejs.org (نسخهٔ LTS) |
| Git | هر نسخهٔ جدید | https://git-scm.com |

> Bun هم کار می‌کند (سریع‌تر است): https://bun.sh — در این راهنما معادل npm را هم می‌نویسیم.

## ۲) دریافت سورس

```bash
git clone https://github.com/soldiermr98-commits/mrdb.git
cd mrdb
git checkout feat/plugin-admin-ui-v1.3   # شاخهٔ کاری؛ بعد از ادغام، main هم کامل است
```

## ۳) تغییرات جزئی — کدام فایل؟

| چه می‌خواهید عوض کنید؟ | کجا؟ |
|---|---|
| متن/تصویر سکشن‌های صفحهٔ اصلی، عنوان «محصولات»، دوره‌های برگزیده | **پیشخوان وردپرس** ← مستر دستباف ← «محتوای وب‌اپ» (بدون بیلد!) |
| صفحات داخلی وب‌اپ و سطح دسترسی | پیشخوان ← «صفحات وب‌اپ» |
| متون ثابت داخل اپ (برچسب‌ها، پیام‌ها) | `src/views/*.tsx` و `src/components/**/*.tsx` |
| رنگ‌ها و ظاهر | `src/index.css` (متغیرهای Tailwind) |
| آدرس API | فایل `.env.production` (بند بعد) |
| منطق پلاگین (REST/پرداخت) | `wordpress-plugin/mrdastbaaf-bridge/` (PHP — نیاز به بیلد ندارد، فقط کپی) |

> ⚠️ اکثر «متن‌ها و عنوان‌ها» از پیشخوان مدیریت می‌شوند و اصلاً نیازی به بیلد ندارند —
> اول همان‌جا امتحان کنید.

## ۴) بیلد وب‌اپ (PWA)

**گام ۱ — نصب وابستگی‌ها (فقط بار اول):**

```bash
npm install          # یا: bun install
```

**گام ۲ — ساخت `.env.production` کنار `package.json`:**

```
VITE_API_BASE_URL=https://mrdastbaaf.com/wp-json/mrdastbaaf/v1
```

> ⚠️ این خط **الزامی** است. بیلد بدون آن (یا با آدرسِ بدون مسیر `/wp-json/...`) عمداً متوقف
> می‌شود — این گارد امنیتی جلوی بیلدِ قطع‌شده از سرور را می‌گیرد.
> اگر حذفش کنید، اپ در «حالت دمو» با دادهٔ ساختگی بالا می‌آید (فقط برای تست محلی).

**گام ۳ — بیلد:**

```bash
npm run build        # یا: bun run build
```

خروجی در پوشهٔ **`dist/`** ساخته می‌شود (شامل `index.html`، `assets/`، `sw.js`، `manifest.webmanifest`).

**گام ۴ — انتشار:**

- محتویات `dist/` را روی هاستِ `app.mrdastbaaf.com` (پوشهٔ ریشه) بارگذاری کنید.
- کاربرانِ نصب‌شده نسخهٔ جدید را با Service Worker ظرف حداکثر ۲۴ ساعت (یا با دو بار بستن/باز کردن) می‌گیرند.

**بازبینی سریع قبل از انتشار:** `npm run lint` (بررسی تایپ) — اگر خطا داد، بیلد سالم نیست.

## ۵) بستهٔ افزونه (بدون بیلد — فقط ZIP)

پلاگین PHP است و بیلد جداگانه ندارد:

```bash
cd wordpress-plugin
zip -r mrdastbaaf-bridge.zip mrdastbaaf-bridge -x "*/tests/*"
```

ZIP حاصل را از پیشخوان ← افزونه‌ها ← بارگذاری افزونه نصب کنید (جایگزین نسخهٔ قبل؛ داده‌ها حفظ می‌شوند).

## ۶) ذخیرهٔ تغییرات در گیت‌هاب (توصیه‌شده)

```bash
git add -A
git commit -m "توضیح تغییر"
git push origin feat/plugin-admin-ui-v1.3
```

---

## چک‌لیست خطاهای رایج

| خطا | علت و حل |
|---|---|
| «بیلد پروداکشن بدون VITE_API_BASE_URL معتبر مجاز نیست» | فایل `.env.production` را طبق گام ۲ بسازید |
| `VITE_API_BASE_URL باید آدرس کامل اندپوینت پل باشد` | باید با `https://` شروع و به `/wp-json/mrdastbaaf/v1` ختم شود |
| اپ بالا می‌آید ولی «خطای اتصال» می‌دهد | آدرس API اشتباه است یا افزونه غیرفعال است |
| تغییرات متنی در اپ دیده نمی‌شود | آن متن از پیشخوان مدیریت می‌شود («محتوای وب‌اپ»)، نه از کد |
